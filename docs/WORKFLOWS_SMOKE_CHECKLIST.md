# Workflows 人工极限烟测清单（终审 · 发版 smoke）

> 级别：第二级验收。定位 = **人工、单人定性、终审 / 发版 smoke**。**不入 CI、不是机器门槛**——
> 机器门槛是第一级假模型 ×7（见 `test/issue-233-final-acceptance.test.mjs`，虚拟钟、分钟级、已在回归里跑绿）。
> 本清单只能由用户本人在全真条件下手动跑一遍：真实端点 + 真实 ChatGPT 网页端 + 真实 TUI，规模约 40 分钟。
> 通过标准（三条，缺一不算过）：**无失控燃烧、无假完整、复活第一眼即可见"活已干完 + 去哪拿"。**

## 前置

- 端点已配置（与 subagent 共用同一 `baseUrl / apiKey / model`，单源不另开）。
- 用一个"要全、要准、单会话装不下"的真实任务起一条多路 run（对话里点名 workflows 或直接给任务）。
- 闸门保持默认（默认即上限）：`tokenCap=8,000,000 / runGate=30 分钟 / agentCap=1000 / 并发窗口 = max(2, min(16, 核数−2))`。
- 记下 `workflow_start` 返回的 `runId` 与 `scriptPath`（绝对路径）。

## 逐项走查（每项记：观察到的事实 → 是否符合通过标准）

1. **长 run 贴闸**
   - 跑一条贴近、或（经我明确授权后）超过默认墙钟上限的长 run。
   - 观察：到 `runGate` 前后，run 在闸内自行收敛为终态，燃烧就地停；不出现"闸过了还在无限烧 token"。
   - 判据：**无失控燃烧**。

2. **缺席 25–35 分钟（超出 GPT 死亡窗）**
   - run 起来、起了汇总体（Reducer）之后，我离开 ChatGPT 网页端 25–35 分钟不轮询。
   - 观察：这段缺席里 run 在本地闸内自走自结；没有任何"等我回来才继续"的卡死。
   - 判据：**无人看管也能收敛**。

3. **复活第一眼（收件箱 + TUI 双侧可见）**
   - 回到 ChatGPT 网页端，第一次读收件箱（或 `session_context`）；同时打开 TUI Workflows 屏。
   - 观察：第一眼即可读到"活已干完 + 摘要绝对路径 + 索引提醒"，不需要我再去试探式轮询；
     TUI 屏上该 run 显示为终态、有产物路径。
   - 判据：**复活第一眼即可见"活已干完 + 去哪拿"**。

4. **等待期 token 零增长（肉眼可验）**
   - 在汇总体阻塞等待终态标记的那段时间（run 在跑、标记未落），观察 token 用量计数。
   - 判据：等待期用量**不增长**（`wait_for_path` 是本地 fs 轮询、模型不参与）；增长只发生在回合之间的"再等一次"。

5. **一次 cancel 与一次 pause→resume**
   - cancel：在 TUI 或对话里对一条在飞 run 点一次取消。观察：燃烧**秒级停止**、队列清空、结算 `cancelled`、三件套照发、
     汇总体醒来报 cancelled partial；再点一次取消 = 幂等返回当前状态，不重复发通知。
   - pause→resume：在 TUI 点一次暂停，隔一会儿再点恢复。观察：暂停期间墙钟不走、汇总体等待预算同规则冻结
     （暂停 20 分钟不该误报 wait-timeout），恢复后原地继续。

6. **worktree 的"有改动保留 / 合并处置"各走一遍**
   - 让某路在 worktree 里产生改动、另一路保持干净。
   - 观察：干净的自动删；**有改动的保留**并在结果回报 `path + branch`；boot-sweep 顺带只清干净的那些；
     TUI Worktrees 面板列出保留项（runId / 路径 / 分支 / 大小 / 时间）。
   - 处置：在面板上手动合并一项、丢弃一项（丢弃审计留痕）。判据：**有改动的 worktree 永不自动删**（唯一减法 = 人）。

7. **满载时汇总体交付是否仍准时（429 风暴场景，假模型测不到、只能真人撞）**
   - 起一条几十路并发的大 run，与自己的直连 subagent / skill fork 同打**同一端点**，逼近限流。
   - 观察：满载撞 429 时，Reducer 聚合回合可能被限流拖慢、交付延迟吃掉 `reduceSlack`（5 分钟）；
     引擎的预算循环与 subagent 的每路 breaker **互不知晓**（这是有意设计，不做跨模块 QoS 仲裁）。
   - 判据：仍**无失控燃烧**、无假完整；交付最迟以 `failed(wait-timeout)` 三段报告如实出现，绝不冒充 completed。

## 记录

- 逐项写"观察到的事实"，附 `runId` / 产物绝对路径 / 时间。
- 任一项触发"失控燃烧 / 假完整 / 复活第一眼看不到产物" → 记为**未过**，开缺陷。
- 全真跑一次即可定性发版；不需要重复次数（重复性由第一级 ×7 保证）。
